# Передача сессии: Обновления безопасности и транспорта

**Контекст:** Пользователь перешел из предыдущей сессии в новую. Этот документ обобщает последние критические изменения в проекте Atrum для обеспечения преемственности.

---

## 1. Безопасность транспортного уровня (NostrTransport.kt)

### Политика «Tor или ничего» (Tor or Nothing)
- **Изменение:** Удалена логика `TOR_FALLBACK_MS` и автоматический переход на прямое соединение для чатов, использующих Tor.
- **Причина:** Предотвращение случайных утечек IP-адреса в агрессивных или публичных сетях. Если чат настроен на работу через Tor, он будет работать *только* через Tor. Прямые соединения в качестве резерва запрещены.

### Механизмы защиты от тайминг-анализа
- **Сетевой джиттер (Network Jitter):** Внедрена случайная задержка (50–300 мс) в методе `publishToAnyRelay` при использовании Tor. Это мешает наблюдателю сопоставить время выхода пакета с устройства со временем его появления на реле.
- **Кворум подтверждений (Confirmation Quorum):** Логика отправки сообщений изменена: теперь приложение ждет подтверждения успеха от **кворума (3 из 5+ реле)**, а не от первого ответившего. Это скрывает, какое именно реле является для пользователя «основным».

## 2. Настройки интерфейса по умолчанию (CreateChatActivity.kt)

- **Путь по умолчанию:** Значение `MsgPath` по умолчанию изменено с `NOSTR` (Direct) на `TOR`.
- **Эффект:** Новые чаты теперь создаются с максимальным уровнем приватности «из коробки». Пользователь должен вручную выбрать «Direct Nostr», если ему важна скорость в ущерб анонимности.

## 3. «Бесшовное» редактирование сообщений (In-place Editing)

- **Проблема:** Раньше при редактировании сообщение исчезало до следующего цикла синхронизации, что создавало ощущение бага.
- **Решение:**
    - **Message.kt:** Добавлено поле `replacingId: String?`. Оно связывает «ожидающее» (pending) сообщение с оригиналом, который оно должно временно заменить в UI.
    - **ChatStore.kt:** Метод `compose()` теперь умеет подставлять сообщение из очереди `replacements` прямо на место оригинального сообщения в списке.
    - **ChatActivity.kt:** Метод `performEdit` теперь создает оптимистичную копию сообщения с `replacingId` и флагом `isPending = true`. Пользователь видит результат мгновенно со значком часов. Только осталась одна проблема, сообщение после редактирования доло стоит в режиме ожидания. Пользователь сказал, что после изменения, состояние ожидания должно пройти почти мгновенно. Я не смог исполнить последнюю просьбу пользователя
