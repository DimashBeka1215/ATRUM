# Atrum Mods SDK

Как написать, подписать и опубликовать мод. **Моды подписываются только издателем Atrum
(тобой). Приватный ключ — офлайн, в приложение не попадает.**

## Модель доверия

- В приложении вшит **публичный** ключ издателя (`ModManager.PUBLISHER_PUBKEY_HEX`,
  Schnorr/secp256k1, hex — как у списка реле) — им проверяется подпись. Публичный ключ не секрет.
- Каждый мод и весь каталог подписаны **приватным** ключом издателя.
- Приложение грузит мод только если: размер в пределах лимита → SHA-256 совпал →
  подпись над `id|version|entryClass|sha256` валидна. Иначе — отказ, код не исполняется.

## Контракт

Мод реализует `com.atrum.chat.mods.AtrumMod` (см. `app/.../mods/ModApi.kt`):

- `id` — стабильный идентификатор (совпадает с каталогом).
- `onLoad(host: ModHost)` — точка входа; здесь мод регистрирует возможности.
- Мод видит только `ModHost` (лог, тост, `registerSettingsItem`). Возможности
  расширяются в Фазе 3, осознанно.

Пример — `HelloMod.kt`.

## Сборка и публикация (пошагово)

1. **Издательский ключ — Schnorr** (тот же, что подписывает список реле; экран «Издатель»).
   Публичный (hex) уже вшит в `ModManager.PUBLISHER_PUBKEY_HEX`. Приватный — у тебя, им
   подписываешь; в приложение для проверки он не нужен. Береги приватный ключ.
2. **Скомпилировать мод** против jar с интерфейсами (`AtrumMod`, `ModHost`) как
   `compileOnly` (в рантайме их даёт хост).
3. **Получить `classes.dex`:** `kotlinc HelloMod.kt -d mod.jar` → `d8 mod.jar --output .`
   → получится `classes.dex`.
4. **Посчитать `sha256(classes.dex)`** (hex).
5. **Подписать мод:** Schnorr-подпись (hex) над `SHA-256("<id>|<version>|<entryClass>|<sha256hex>")`
   издательским приватным ключом → поле `signature` в каталоге.
6. **Подписать каталог:** Schnorr-подпись (hex) над `SHA-256("<v>|<id>:<version>|...")`
   (порядок из массива `mods`) → поле `sig`.
7. **Опубликовать** `classes.dex` и `catalog.json` на Source (raw). URL каталога →
   `ModManager.CATALOG_URL`, URL dex → поле `dexUrl`.
8. **Проверить в приложении:** Настройки → Моды → Установить.

Формат каталога — `catalog.example.json`.

## Статус

- Фаза 1: каталог + проверка подписи + экран «Моды». ✅
- Фаза 2: загрузчик `.dex` (verify-before-execute, InMemoryDexClassLoader). ✅ (код готов,
  **не протестирован end-to-end** — нужен реальный подписанный мод; перед боевым
  использованием — совместный ревью загрузчика).
- Фаза 3: расширение `ModHost` под конкретные моды, экран подраздела мода, персистентность
  установленных/включённых, kill-switch отозванных версий.
