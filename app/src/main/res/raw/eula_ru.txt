ПОЛЬЗОВАТЕЛЬСКОЕ СОГЛАШЕНИЕ

1. Общие положения
Приложение является технической системой для обмена зашифрованными сообщениями между пользователями. Приложение не является оператором связи и не контролирует содержимое сообщений.

2. Единая модель приватности и архитектуры
Настоящий документ одновременно описывает: условия использования сервиса, модель обработки данных, архитектурные ограничения системы.

3. Zero-Knowledge архитектура (ключевая модель)
Система спроектирована как zero-knowledge транспортный слой. Разработчики не имеют доступа к ключам шифрования, не могут расшифровывать сообщения, не имеют доступа к содержимому сообщений, не обладают возможностью восстановления пользовательских данных.

4. Сквозное шифрование (E2EE)
Сообщения шифруются на устройстве отправителя, расшифровываются только на устройстве получателя, передаются исключительно в зашифрованном виде.

5. Модель данных (Data Lifecycle Definition)
Система работает по принципу: данные создаются на устройствах пользователей, данные существуют в зашифрованной форме во время передачи, система не является хранилищем данных, после доставки данные не сохраняются в расшифрованном виде.

6. Отсутствие хранения и retention policy
Система не предназначена для хранения пользовательских сообщений. Любые данные не сохраняются в расшифрованном виде, не индексируются, не используются для профилирования.

7. Метаданные и ограничения прозрачности
Даже при использовании zero-knowledge архитектуры сеть может создавать технические метаданные. GitHub и сторонние сервисы могут логировать технические данные. Разработчики не контролируют эти процессы.

8. Сторонняя инфраструктура (Untrusted Transport Layer)
Система использует GitHub, API сторонних сервисов, пользовательские узлы. GitHub и аналогичные сервисы не являются доверенными хранилищами и используются только как транспорт зашифрованных данных.

9. Модель угроз (Threat Model)
Система НЕ защищает от: компрометации устройств пользователей, вредоносного ПО на устройстве, перехвата трафика на уровне сети, ошибок пользователя в управлении ключами. Система защищает только содержимое сообщений при корректной работе E2EE.

10. Управление ключами
Пользователь полностью контролирует ключи шифрования и несёт полную ответственность за их сохранность. Потеря ключей = невозможность восстановления данных.

11. Отсутствие аккаунтов и идентификации
Сервис не требует регистрации, не использует аккаунты, не идентифицирует пользователей.

12. Очистка данных (Data Minimization)
Система не предназначена для обработки персональных данных, идентификаторов устройств, профилирующей информации.

13. Пользовательская инфраструктура
Пользовательские узлы или серверы считаются независимой инфраструктурой, полностью под ответственностью пользователя.

14. AI-assisted разработка
Продукт создан с использованием инструментов искусственного интеллекта для генерации и сопровождения кода. Это не влияет на функциональность, безопасность или юридическую природу сервиса.

15. Лимитация доступа и юридические запросы
Разработчики не могут расшифровать сообщения, не имеют доступа к ключам, не хранят пользовательские данные. При юридических запросах может быть предоставлена только реально существующая техническая информация. Содержимое сообщений не может быть раскрыто. Отсутствующие данные не могут быть восстановлены.

16. Модерация и контроль доступа
Разработчики могут ограничивать доступ, предотвращать злоупотребления, защищать инфраструктуру.

17. Source-Available лицензия
Код доступен только для просмотра и аудита безопасности. Запрещены модификации, форки, распространение, использование в других продуктах.

18. Отказ от гарантий
Сервис предоставляется "как есть".

19. Ограничение ответственности
Разработчики не несут ответственности за действия пользователей, потерю данных, сбои инфраструктуры, сторонние сервисы.

20. Форс-мажор
Сервис может быть недоступен из-за внешних факторов вне контроля разработчиков.

21. Отсутствие доверительных обязательств
Между пользователем и разработчиком не возникает фидуциарных, агентских или специальных обязанностей.

22. Изменение условий
Условия могут быть изменены в любое время.

23. Применимое право
Определяется юрисдикцией оператора.

24. Делимость положений
Недействительность одного положения не влияет на остальные.

25. Полное соглашение
Настоящий документ объединяет условия использования, модель обработки данных, описание архитектуры системы.
